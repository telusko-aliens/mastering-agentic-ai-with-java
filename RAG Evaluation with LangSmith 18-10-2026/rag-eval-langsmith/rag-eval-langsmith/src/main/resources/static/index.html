What each span covers

Spring AI traces the model call by itself. The retrieval around it is not traced automatically, so those spans are created in the application. In a RAG system the retrieval is usually what went wrong, and a trace without it shows a slow answer and no reason.

How to read a trace in LangSmith

1. smith.langchain.com, then the project java-rag-evaluation-demo
2. Open the newest trace. Every question is one trace.
3. The tree is:

     POST /api/rag/ask
       rag.retrieval      how many chunks came back, for which question
       rag.generation     the model call
         chat gpt-4.1-mini    tokens and timing, added by Spring AI

4. Click rag.retrieval and read documents_retrieved. If it is 0, the answer
   was a refusal and no model was called at all.
5. A slow trace with a fast rag.generation means retrieval was the problem,
   not the model.

Run the dataset

Twelve questions, ten answerable from the document and two not. Every question goes through the real pipeline. Expect about a minute per run.
